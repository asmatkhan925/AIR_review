# Table 3. Adaptation Strategy Decision Matrix

Purpose: Manuscript-ready draft table for Section 8. Source basis: `05_synthesis_matrices/adaptation_strategy_matrix.csv`, Block G synthesis controls, and `07_draft_sections/08_adaptation_strategies_low_resource_asr.md`.

| Low-resource condition | Candidate adaptation strategy | Why it may help | Main risk | Required evaluation/reporting control |
|---|---|---|---|---|
| A small but reliable labeled target-language set is available | Full fine-tuning of a pretrained SSL, multilingual, or weakly supervised ASR model | Directly specializes the model to the target transcripts, acoustics, and recognition objective | Overfitting, compute cost, and hidden degradation on dialects, domains, or existing languages | Report target-data size, model checkpoint, decoding settings, compute, language/domain breakdowns, and comparison to the unfine-tuned baseline |
| Unlabeled target-language, target-domain, or closely related speech is available but labels are scarce | Continued pretraining before supervised adaptation | Aligns representations with target acoustics, domain, or language variety before final ASR tuning | Unlabeled data quality, provenance, domain skew, and compute burden can dominate the result | Report unlabeled-data source, filtering, duration if locally known, continued-pretraining budget, target-domain tests, and downstream supervised evaluation |
| Compute, storage, or multi-language deployment constraints limit full fine-tuning | Adapter tuning or adapter pre-training | Adds or tunes smaller language/domain-specific modules while keeping most model parameters fixed | General adapter evidence is not always direct ASR evidence; adapter gains may be model- and benchmark-specific | Report trainable parameters, memory, base model, matched full-fine-tuning comparison where possible, and language/domain breakdowns |
| Large models are useful but memory or trainable-parameter budget is constrained | LoRA or QLoRA-style parameter-efficient tuning | Low-rank or quantized adaptation can reduce trainable parameters or memory requirements | Core evidence includes general method anchors; ASR-specific LoRA evidence remains partly watchlist-level | Separate method-definition claims from ASR performance claims; report trainable parameters, quantization, memory, latency, and direct ASR validation |
| A related language, donor corpus, or multilingual model may support the target language | Related-language or cross-lingual transfer | Can exploit phonetic, typological, or multilingual representation overlap when target labels are limited | Donor-language mismatch can produce weak or biased transfer, and aggregate multilingual gains can hide target-language failures | Report donor-language rationale, target-language evaluation, language-family or script mismatch, and per-language rather than pooled results only |
| Target vocabulary, code-switching, named entities, or context may influence recognition | Prompting, contextual biasing, or constrained context use | Can guide recognition or correction toward relevant vocabulary or domain terms | Watchlist and emerging evidence cannot support strong central claims; context can leak answers or encourage over-correction | Use only bounded wording; report context source, constraints, leakage checks, named-entity behavior, hallucination, and over-correction tests |
| A new low-resource language is added to an existing multilingual system | Forgetting-aware new-language adaptation | Balances target-language improvement with retention of existing multilingual capability | Direct fine-tuning may improve the new language while degrading existing languages; parameter-efficient methods may trade target gains for retention | Report target-language gains, prior-language retention, forgetting metrics, trainable parameters, and whether the evaluation includes both new and existing languages |
